## Requirements

### R1. Мир, Чанки и базовая физика сыпучих и жидких материалов (ШАГ 2)
- Реализовать систему чанков 64x64 клеток со структурой данных SoA (Structure of Arrays), выровненной по строке кэша (cache line aligned).
- Реализовать MaterialRegistry с загрузкой параметров материалов из файлов `assets/materials/*.json`.
- Реализовать симуляцию движения материалов типа POWDER (песок) и LIQUID (вода) с учетом плотности, гравитации и взаимного вытеснения.
- Реализовать рендеринг пиксельного мира через streaming texture с фильтрацией GL_NEAREST.
- Реализовать инструмент кисти для интерактивного взаимодействия (ЛКМ — рисование материалом, ПКМ — стирание, колесико мыши — изменение радиуса).

### R2. Термодинамика, реакции, газы и взрывы (ШАГ 3)
- Реализовать диффузию тепла между соседними клетками и фазовые переходы материалов при достижении температур плавления, кипения или конденсации.
- Реализовать ReactionSystem для химических и физических взаимодействий между материалами на основе конфигурации `reactions.json`.
- Реализовать физику газообразных материалов (GAS) и горения/пламени (FIRE) с учетом времени жизни и подъема вверх.
- Реализовать ExplosionSystem для моделирования взрывов с распространением ударной волны, механическим разрушением материалов и термическим эффектом.

### R3. Многопоточная симуляция и оптимизация производительности (ШАГ 4)
- Реализовать параллельное обновление чанков по 4-фазной схеме шахматной доски (4-phase checkerboard decomposition) для исключения race conditions без блокировок отдельных клеток.
- Реализовать механизм спящих чанков (sleeping chunks) с каскадным пробуждением при активности на границах и взаимодействиях.
- Обеспечить оптимизацию производительности симуляции под 300 000+ одновременно активных клеток при стабильной частоте обновления 60 TPS.

### R4. Пользовательский интерфейс, сохранение/загрузка, документация и тесты (ШАГ 5)
- Реализовать интерфейс на Dear ImGui: палитра материалов с группировкой по категориям, выбор кистей и параметров, слайдеры скорости симуляции и вектора гравитации, экран отладки (F3) со счетчиками FPS, TPS, числа активных чанков и клеток.
- Реализовать систему сериализации/десериализации состояния мира в бинарный формат с RLE-сжатием для быстрого сохранения и загрузки.
- Разработать CTest модульные тесты для ключевых компонентов (физика материалов, термодинамика и реакции, RLE-сериализация, корректность параллельного обновления).
- Разработать консольный режим бенчмарка (запуск без GUI через аргумент командной строки `--benchmark`), проводящий автоматический замер производительности симуляции на сетке с 300 000+ активных клеток.
- Подготовить и актуализировать проектную документацию в файлах `README.md` и `ARCHITECTURE.md`.

## Acceptance Criteria

### Симуляция и рендеринг
- [ ] Чанки 64x64 организованы по схеме SoA с выравниванием по строке кэша.
- [ ] MaterialRegistry корректно парсит свойства материалов из `assets/materials/*.json` и регистрирует их в системе.
- [ ] Сыпучие материалы (POWDER) формируют устойчивые откосы, а жидкие (LIQUID) растекаются в стороны и вытесняются в соответствии с относительной плотностью.
- [ ] Пиксельный мир отрисовывается через streaming texture с фильтрацией GL_NEAREST без графических артефактов.
- [ ] Инструмент кисти поддерживает рисование выбранным материалом (ЛКМ), стирание (ПКМ) и динамическое изменение размера колесиком мыши.

### Термодинамика, реакции и взрывы
- [ ] Тепло распространяется между соседними клетками по законам диффузии, и материалы переходят в другие фазовые состояния при достижении пороговых температур.
- [ ] Взаимодействия между контактирующими клетками выполняются согласно правилам из `reactions.json`.
- [ ] Газы и частицы огня поднимаются вверх, рассеиваются или сгорают по истечении времени жизни.
- [ ] Взрывы распространяют ударную волну, разрушают блоки в радиусе поражения и вызывают термические реакции.

### Многопоточность и бенчмаркинг
- [ ] Многопоточное обновление по 4-фазному шахматному паттерну (4-phase checkerboard) выполняется детерминированно и без гонок данных (data races).
- [ ] Спящие чанки корректно исключаются из симуляции до момента каскадного пробуждения.
- [ ] Консольный бенчмарк (`--benchmark`) подтверждает способность движка обрабатывать не менее 300 000 активных клеток с частотой не менее 60 TPS (время шага симуляции <= 16.6 мс).

### Интерфейс, сохранение и документация
- [ ] Интерфейс Dear ImGui предоставляет полнофункциональную палитру материалов, управление симуляцией и экран F3-отладки.
- [ ] Сохранение и последующая загрузка мира в бинарный RLE-формат восстанавливают полное состояние всех клеток без потерь.
- [ ] Все модульные тесты успешно компилируются и проходят через `ctest`.
- [ ] Файлы `README.md` и `ARCHITECTURE.md` содержат актуальные инструкции по сборке, описания архитектуры и модулей проекта.
